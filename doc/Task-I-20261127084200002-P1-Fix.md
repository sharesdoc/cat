## 2. 问题描述

### 现象
当 `SensitiveFileChecker` 模块级 `set_checker()` 未调用时，`cat_search_text` 不报错，而是静默跳过所有敏感文件检查继续搜索。

### 复现步骤
1. `TextSearcher(root_path)` 未传入 `sensitive_checker` 参数（当前 handler 的实现的确如此）
2. 模块级 `set_checker()` 未在搜索前调用 → `is_sensitive()` 抛 `RuntimeError`
3. `_check_sensitive()` 中 `except RuntimeError: pass` 吞掉异常
4. 搜索正常执行，绕过全部敏感文件保护

### 根因分析（待确认）
_handler 调用 `TextSearcher(root_path)` 未传入 checker；`_check_sensitive()` 中 `except RuntimeError: pass` 过于宽松。

## 3. 解决方案（待定）

方案 B（推荐）：handler 级别确保 `TextSearcher` 构造时传入 `get_checker()` 实例，并将 `except RuntimeError: pass` 改为 `logger.warning`。

## 4. 回归测试

- `set_checker()` 未调用时 `cat_search_text` 应返回错误
