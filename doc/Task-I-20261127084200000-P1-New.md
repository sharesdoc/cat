## 2. 问题描述

### 现象
调用 `cat_search_text` 并指定 `path` 参数为敏感文件时（如 `.git/config`），文件内容被搜索并返回，而非被拒绝访问。

### 复现步骤
1. 调用 `cat_search_text`，参数 `path=".git/config"`，`query="remote"`，`mode="literal"`
2. 服务器的 `.git/config` 中匹配的行与上下文被返回
3. 预期的行为：应因敏感文件拒绝访问，返回空结果或错误

### 根因分析（待确认）
`search()` 方法中，`is_single_file` 分支（第 219-239 行）直接调用 `_search_file_at()` 而不先调用 `self._check_sensitive(file_rel)`。对比目录遍历分支（第 270-274 行），后者在执行搜索前做了敏感文件检查。

## 3. 解决方案（待定）

在 `is_single_file` 块中 `_search_file_at()` 调用之前插入 `self._check_sensitive(search_root_rel)`。

## 4. 回归测试

- 单文件搜索 `.git/config` 返回空结果
- 单文件搜索 `.env` 返回空结果
- 目录遍历搜索仍能正确过滤敏感文件
